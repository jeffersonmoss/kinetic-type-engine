# Target Design v1 for the Kinetic Type Engine

Written by Fable (claude-fable-5-2) as architect of the engine council, 21 November 2026. It merges the six round files in this folder (Round 1 and Round 2 from Fable, Astra and Neon) into one target that all three can score.

## Read this first: what is and is not verified

1. Nothing in this design has been built, rendered or watched. It is a design on paper. I read engine source and the round files; I launched no browser and ran no render.
2. The thresholds and defaults here (lead frames, share percentages, cap fractions, severity tiers) are the council's working numbers, not Jefferson's. The only limits taken from the coordinator's brief are: no drop shadows, no props or figures in the default path, parentheses never shown, display spellings, visible for at least 15 frames at opacity 0.5 or more, at most one state change per beat.
3. Unverified claims this design leans on, each of which a build step must prove before relying on it:
   3.1. `TypeStage` can be rendered to a string in node with `react-dom/server`. I confirmed it takes `t` as a prop and that my search found no React hooks in `TypeStage.tsx` or `smear.tsx`, and that `react-dom` 19.3.1 is installed. I did not run it.
   3.2. Deep-freezing compiled boards does not break the engine. I did not check every engine function for mutation of its input board.
   3.3. Neon's claims about smear ordering and per-letter `textLength` in `TypeStage`, and Astra's assembled-film counts (223 turn, 120 rise, 111 glide of 513 entrances in the Ball master), are taken from their files and not re-derived by me.
   3.4. The Room for One word times used in the worked example come from the Suno alignment as corrected by a script. Nobody has listened to check them.
   3.5. All effort and ordering judgments in Section 8 are estimates.
4. The status column in Section 3 ("exists") reflects my reading of the working tree. Several of those effects exist only in the uncommitted working tree, which is why Section 7 starts by committing it.
5. One limit on the "one command" promise: a node command line tool cannot call the Suno connector, which is an agent tool. `kte new` therefore takes files. The agent fetches the mp3 and the alignment by clip id and then runs one command. See item 108.

## Section 1. Modules and their boundaries

The engine stays one repository at `~/Experiments/Kinetic Type Engine/`. This is the existing engine reorganised and extended, not a new engine. The existing `engine/` folder is kept in place and becomes the frame core; new modules are added beside it. Nothing in `engine/` is renamed in v1.

### File layout

```
Kinetic Type Engine/
  engine/                 frame core (exists): types, config, layout, wordState, rig,
                          TypeStage, smear, verbs, emergence/, validate*, time
  context/                NEW  EngineContext, formats, look, withEngine bridge
  song/                   NEW  song import: alignment to song map v2, ear check list
  effects/                NEW  defineEffect, extendEffect, cascade, reverse, catalogue,
                          one file per new effect, adapters over engine verbs
  score/                  NEW  authoring types and builders: film, scene, line, motif,

  check/                  NEW  schema, compile, board, sync, hull, variety, golden

  cli/                    NEW  kte commands
  bin/kte                 NEW  launcher that dispatches to the film's pinned release
  fixtures/               NEW  pure-type fixture scores, golden hashes, effects reel

  props/                  exists, untouched, optional legacy, not in the default export
  tools/                  exists; validate-boards.mjs stays until check/ replaces it
  reviews/                exists
```

### Module boundaries

6. `song` (song import). Input: an audio file, a Suno alignment JSON, an optional `song.json` of display spellings. Output: `analysis/song-map.json` in schema version 2, plus `analysis/Ear check list.md`. It imports nothing from any other module. It replaces the hard-coded input name and the line-end-only fix in the skill's `build_song_map.py`. Written in TypeScript and run by node so the whole tool chain is one runtime.
7. `score` (authoring surface). Pure data builders and types. It imports types from `song` and effect signatures from `effects`. It performs no layout and reads no configuration. A score file is a TypeScript module whose default export is the value returned by `film(...)`.
8. `effects`. Typed effect definitions. Each effect is a pure function of normalised time, the unit it acts on, typed parameters and an environment. It imports only `engine` types and `context`. Existing verbs in `engine/verbs.tsx` and `engine/emergence/` are wrapped by adapters, not rewritten.
9. `compile`. `compileScore(ctx, score, songMap)` is pure and returns a `CompiledFilm`: frozen `Board[]` for one format, a line index (line id to board, block, landing frame), the transition list, and diagnostics. It imports `score`, `effects`, `song` types and `engine` layout. It never reads the module singleton.
10. `frameAt` (the frame core, which is today's `engine/`). `wordStateAt(board, i, f)` stays the single state function shared by the renderer and every check. The core imports nothing from `score`, `compile`, `check`, `host` or `cli`. Its only Remotion import stays `useCurrentFrame` in `engine/time.ts`.
11. `check`. Everything that judges a film without a browser, plus the list of frames a browser must render. It imports `compile` and `engine`. Section 6 defines it.
12. `host`. The only place a Remotion project exists. It loads a film folder named by an environment variable, compiles its score once per format, and registers compositions. A film folder contains no Remotion config, no `package.json`, no `node_modules` and no React components.
13. `cli`. `kte` commands that call the modules above. Section 5 defines them.
14. `props` (optional legacy). The engine already imports nothing from `props/`. It stays where it is, is left out of the default export and the documentation, and is reachable only through an explicit `legacy/props` import. No score builder accepts a prop or a figure.

### Dependency rule

15. Allowed imports, and no others: `song` imports nothing; `context` imports `engine/types`; `effects` imports `engine`, `context`; `score` imports `song`, `effects`; `compile` imports `score`, `effects`, `song`, `engine`, `context`; `check` imports `compile`, `engine`, `context`; `host` imports `compile`, `engine`, `context`, `remotion`; `cli` imports everything. A check in step 4 of Section 8 enforces this with a 30-line script that greps import paths.

### The engine context

16. `EngineContext` is a frozen object: `{format, safeBox, fps, beatFrames, look, fontMetrics, limits}`. `format` is `WIDE` or `SHORT_916` from the existing `FrameFormat`. `safeBox` is derived from the format insets (for `SHORT_916`: 564 by 921.6). `limits` holds every numeric limit as a function of the safe box, never a fixed pixel constant.
17. `createContext({format, look, songMap})` builds one. New code receives `ctx` as an argument.
18. `withEngine(ctx, fn)` is the one bridge to the legacy singleton. It calls `configureEngine` with the context's values, runs `fn` synchronously, and restores the previous values in a `finally`. `TypeStage`, `layoutBoard` and `validateBoards` are called only inside it until they take `ctx` directly. `fn` must be synchronous; `withEngine` throws if `fn` returns a promise.
19. Compiled boards for the two formats are separate objects. The twelve `WeakMap` caches keyed on `Board` therefore cannot mix formats.

## Section 2. The score and line-card format

### Structure

20. A film is `film({song, look, formats, scenes})`.
21. A scene is `scene(id, {ground, lines, exit})`. One scene compiles to one `Board`. Lines inside a scene accumulate on the same board and the camera rig travels between them, which is how the Pulp Fiction exemplar works. A new scene starts only where the picture is deliberately wiped.
22. A line is `line(id, card)`. The id is the stable song-map line id (for example `h1.2`). The card fields:
    22.1. `rows`: `'auto'` (default) or an explicit array of row specs. Row text comes from the song map display spellings, so the card names words, not timings.
    22.2. `from`: the source landmark on the arrangement already on screen. Required unless the line is the scene opener.
    22.3. `enter`: an effect call from the entrance or transform tables in Section 3, optionally wrapped in `cascade(...)`.
    22.4. `old`: the fate of the previous line at this line's entrance. One of `stay()`, `dock('margin' | 'spine')`, `retract()`, `clear(exitEffect)`, or omitted when the entrance itself consumes the old line (the effect declares `dismissesOld`).
    22.5. `reply`: an optional second voice (Suno ad-lib tokens). It has its own `rows`, `from`, `enter` and `size`, and is timed to the ad-lib tokens.
    22.6. `camera`: a camera recipe. Default is `follow()`, which keeps the landing word inside the safe box.
    22.7. `accents`: effects on sung words, at most one per beat per block.
    22.8. `portrait`: a partial card applied only when compiling `SHORT_916`.
    22.9. `repeat: 'intended'`: silences the variety report for a deliberate repeat.
23. A landmark is one of: `word(lineId, 'TEXT')`, `glyph(lineId, 'TEXT', 'L', {part})` using the existing letter anatomy anchors, `row(lineId, n)`, `rule(ruleId)`, `edge('L' | 'R' | 'T' | 'B')`, `opening()`, or `free({x, y}, reason)`. A bare point with no reason is a compile error. `lineId + '.reply'` addresses a reply.
24. A motif is `motif(name, {lines}, {occurrences})`. It expands to ordinary lines with ids `<name><n>.<k>`. Each occurrence may override any card field of any line.
25. `raw(id, (ctx) => Board[])` is the escape hatch for a passage the format cannot yet say. `kte check` reports the share of lines that used it.

### How the compiler reads a transition pair

26. The pair (previous arrangement, incoming line) is the unit of authorship. The compiler, not the author, owns the life of the source.
27. Landing frame = onset frame of the line's first sung token minus `ctx.limits.lead` (2 frames; ours). Entrance start = landing frame minus the effect's duration. Durations come from the effect definition and are clamped by the energy transit model that already exists (12 frames free transit, 8 frames rest read).
28. The source landmark must be visible (opacity at least 0.5, inside the frame) from entrance start to the frame the effect declares as its release. If it is not, compile fails with the line id, the landmark and the frame.
29. `old` is applied to the previous line at the incoming line's entrance start. If the previous line's last sung token ends later than that, compile fails with a named conflict instead of silently hiding a word that is still being sung.
30. A field left out is a compile warning in draft and a compile error for a master. `kte draft` (item 114) can fill unfilled `from` and `enter` fields and writes its choices into the score file as `auto('turn')`, so a first draft exists quickly and every automatic choice is visible and replaceable.

### Worked example: Room for One (LeBron Glaze)

The hook is four call and response lines and returns three times (song lines 0 to 3, 16 to 19, 34 to 37). The lead vocal is the call and the Suno ad-lib is the reply. Word times are in the song map; the card names none of them.

```ts
// score/hook.ts
import {motif, line, word, glyph, opening, cascade, clear, dock, retract, stay} from 'kte/score';
import {stamp, type, nest, matchCut, rise, quarterRoll, slotRoll, repeatStack,
        fall, zoomLadder, turnIn, beatPunch, follow} from 'kte/effects';

export const hook = motif('h', {
  lines: {
    // "Four rings on his hand! (Room for one!)"
    1: line('h.1', {
      rows: [{text: 'FOUR', size: 'hero'}, 'RINGS ON HIS HAND'],
      from: opening(),
      enter: cascade(stamp(), {by: 'word', clock: 'sung'}),
      reply: {
        rows: ['ROOM FOR ONE'],
        size: 'second',
        from: glyph('h.1', 'FOUR', 'O', {part: 'counter'}),
        enter: nest(),                       // the reply sits inside the O: room for one
      },
      camera: follow(),
      accents: [beatPunch('HAND')],
    }),

    // "Year twenty-four! (Still not done!)"
    2: line('h.2', {
      rows: ['YEAR', {text: 'TWENTY-FOUR', size: 'hero'}],
      from: word('h.1', 'FOUR'),
      enter: matchCut({keep: 'FOUR', pin: 'screen'}),   // FOUR never leaves the screen
      old: clear(retract()),                 // the rest of line 1 goes back the way it came
      reply: {
        rows: ['STILL NOT DONE'],
        size: 'second',
        from: row('h.2', 2),
        enter: cascade(rise(), {by: 'word', clock: 'sung'}),
      },
    }),

    // "Who's still chasing? (The King! The King!)"
    3: line('h.3', {
      rows: ["WHO'S STILL", {text: 'CHASING?', size: 'hero'}],
      from: word('h.2.reply', 'STILL'),
      enter: matchCut({keep: 'STILL', pin: 'board'}),
      old: dock('margin'),                   // line 2 quarter-rolls into a margin note
      camera: quarterRoll({dir: 'cw'}),
      reply: {
        rows: ['THE KING!'],
        from: glyph('h.3', 'CHASING?', 'G', {part: 'foot'}),
        enter: repeatStack({times: 2, clock: 'sung'}),
      },
    }),

    // "What's he chasing? (One more ring!)"
    4: line('h.4', {
      rows: ["WHAT'S HE", {text: 'CHASING?', size: 'hero'}],
      from: row('h.3', 1),
      enter: slotRoll({keep: 'CHASING?'}),   // only the changed words roll over
      reply: {
        rows: ['ONE MORE', {text: 'RING!', size: 'hero'}],
        from: word('h.3.reply', 'KING!'),
        enter: matchCut({keep: 'ING!', pin: 'screen'}),  // KING becomes RING
      },
    }),
  },
}, {
  occurrences: {
    2: {1: {from: edge('B'), enter: turnIn({axis: 'x'})}},
    3: {
      1: {from: word('count.2', 'THREE'), enter: stamp()},
      3: {camera: zoomLadder({steps: 2})},
    },
  },
});
```

```ts
// score/verse1.ts, first line: "At forty-one, LeBron gets Father Time to bite."
line('v1.1', {
  rows: ['AT', {text: 'FORTY-ONE', size: 'hero'}, 'LEBRON GETS', 'FATHER TIME TO BITE'],
  from: word('h1.4.reply', 'ONE'),
  enter: matchCut({keep: 'ONE', pin: 'screen'}),   // ONE MORE RING hands ONE to FORTY-ONE
  old: clear(fall()),                              // the hook drops away; the verse is a new page
  camera: follow(),
  portrait: {rows: ['AT', {text: 'FORTY', size: 'hero'}, {text: 'ONE', size: 'hero'},
                    'LEBRON', 'GETS FATHER', 'TIME TO BITE']},
})
```

31. What the example shows:
    31.1. Every line names what it grows from: the O of FOUR, the word FOUR, the word STILL, the changed row, the ING of KING, the word ONE.
    31.2. Every line says what happens to the one before it: retract, dock to the margin, be consumed by a roll, fall away.
    31.3. The refrain is written once. Occurrence 2 changes how it arrives; occurrence 3 grows out of the count-in ("One! Two! Three!") and escalates the camera.
    31.4. No frame number, no pixel coordinate and no parenthesis appears in the score.
32. The example is a format demonstration, not a storyboard. The choices in it are mine and are not signed off by anyone.

## Section 4. Taste defaults baked in

107. These are defaults of the engine and the importer, so a new film gets them without anyone remembering them.
     107.1. No drop shadows. `look.shadow` defaults to `false`. The default at `TypeStage.tsx:66` (shadow on for tier 2 and above on dark grounds) and the plate shadows at lines 113, 141 and 165 are removed from the default path. A shadow appears only if a look sets it explicitly, and `kte check` reports that as a hard error unless the film's `film.json` carries `"allowShadow": true`.
     107.2. No props and no figures in the default path. No score builder takes one. `props/` is optional legacy.
     107.3. Parentheses are stripped in data. The importer removes `(` and `)` from display text, marks those tokens `role: 'adlib'`, and keeps the raw text beside it. A check fails if any rendered string contains a parenthesis.
     107.4. Display spellings are applied in data. The importer applies `song.json` pronunciations (for Room for One: Luh-BRON to LeBron, Ty-REESE to Tyrese, MAK-see to Maxey, Em-Vee-Pee to MVP and the rest). A check fails if any sung-spelling key from `song.json` appears in rendered text.
     107.5. Legibility. A word in its reading role is visible for at least 15 frames at opacity 0.5 or more. `VISIBLE_THRESHOLD` rises from 0.25 to 0.5. This applies to the interval the word is meant to be read in; a retired word dimmed to 0.45 is not being read and is not counted.
     107.6. At most one state change per beat per block, as the engine already enforces through `BEAT_FRAMES`. A camera accent counts.
     107.7. Minimum sung cap height is a fraction of the safe box short edge (7.5 percent; ours), replacing the fixed 56 px. Giant-word limits are fractions of the safe box, replacing 240 and 800 px, which cannot be met at 720 wide.
     107.8. Contrast of type on its ground is at least 4.5 to 1 (ours).
     107.9. The rig centres on the safe box centre and `fill` uses the safe box, so portrait type is not composed under the platform overlays.

## Section 5. `kte new`: one-command setup

108. The command:

```
kte new "Room for One" --audio "<path to mp3>" --alignment "<path to Suno alignment json>" --suno-clip 77c334f8-edae-47f6-bb68-877d66123a4f
```

   The agent obtains the mp3 and alignment through the Suno connector by clip id, then runs this. `--suno-clip` is recorded as metadata only. `--here <folder>` adopts an existing folder (Room for One already has one) instead of creating a new one, and never overwrites a file that exists.

109. What it creates, in `~/Experiments/<Title> Music Video/`:

```
film.json                      engine tag, title, suno clip id, audio path, formats, edit list
song.json                      display spellings (empty template, or kept if present)
audio/<title>.mp3              copied in
analysis/song-map.json         schema 2: lines, tokens, roles, stable ids, raw timing kept
analysis/Ear check list.md     numbered uncertain spots with times
look.ts                        palette and fonts, shadow off
score/index.ts                 film() with one scene per detected section, lines listed, fields unfilled
score/<section>.ts             one file per section
renders/                       empty
reviews/                       empty
README.md                      the three commands to run next
```

110. It also writes a pointer file in the project folder that owns the song (the caller passes `--pointer <folder>`), naming the workspace path, as his work-product rule asks.
111. The film folder has no `package.json`, no `node_modules`, no Remotion config, no entry file and no copied engine code. There is no per-video hand setup.
112. Pinning. `film.json` carries `"engine": "v1.0.0"`. `bin/kte` reads the tag and runs the `cli/` of that release from `~/Experiments/Kinetic Type Engine Releases/<tag>/`. `kte release install <tag>` creates that folder from the tag with `git archive`, runs `npm ci` from the lockfile, and writes a README stating that it is recreatable from the tag. A release folder is never edited.
113. `"engine": "dev"` runs the working tree, for engine development. `kte render --master` refuses a `dev` pin.
114. The other commands:
     114.1. `kte ingest`: rebuild the song map after a spelling or timing correction, preserving line ids.
     114.2. `kte draft`: fill unfilled `from` and `enter` fields and stamp them `auto(...)` in the score file.
     114.3. `kte check [--format]`: all checks in Section 6 that need no browser; writes `reviews/Check report.md` and `reviews/Frames to inspect.json`.
     114.4. `kte render [--section id] [--format] [--draft | --master]`: Remotion render through the host. `--draft` is 480p with audio.
     114.5. `kte sheet`: stills of the frames listed for inspection, from the browser renderer.
     114.6. `kte where 1:23`: the line id, scene and score file at a time, so "the bit at 1:23" resolves in one call.

## Section 6. Checks

116. Checks run in this order; each stops the next only on hard errors.
     116.1. Score check. TypeScript types plus a runtime schema: unknown line ids, unknown landmarks, effect parameters out of range, a prop or figure anywhere.
     116.2. Compile check. Source visibility (item 28), old line still singing (item 29), unfilled fields, `raw` share.
     116.3. Board validator. The existing rule set, now reading limits from `ctx.limits`, with two repairs: unknown handoff ids are errors (today they pass at `validate.ts:584`), and `sheetRules` and energy transit rules are on by default.
     116.4. Sync evidence. A table per line: token onset frame, landing frame, difference. Plus the state of the ear check list.
     116.5. Hull pass. Described in item 118.
     116.6. Variety report. Described in item 120.
     116.7. Golden frames. Described in item 121.
117. Severity, three tiers (Neon's structure, adopted):
     117.1. Hard errors, which block a master: broken or invisible source, missing glyph, shadow on without the flag, a parenthesis or sung spelling on screen, contrast under 4.5, cap under the format floor, ink outside the frame or the safe box, unintended overlap of two reading words, a landing more than 6 frames early or more than 2 frames late against the token onset, a word read for fewer than 15 frames, two state changes in one beat, an unresolved ear check item on a line.
     117.2. Waivable warnings, each waived in the score with a reason: lead other than the default, rest read under 8 frames, `free` placement.
     117.3. Reports, never blocking: variety, `raw` share, film-local effects in use, portrait override share.
118. Viewer-true checks, as Astra resolved and the coordinator asked:
     118.1. Every effect declares its ink: the box its unit draws at normalised time `u`, including per-letter offsets. This closes the validator's blindness to per-letter mods and ghosts.
     118.2. A coarse hull pass in node walks every frame, unions the declared ink, and flags frames where ink leaves the safe box, two reading words overlap, or a word is under the size floor. It is deliberately conservative: it selects frames to look at; it does not pass a film.
     118.3. The flagged frames, plus a fixed sample (each line's landing frame and the middle frame of each transition), are written to `reviews/Frames to inspect.json`.
     118.4. Those frames are rendered in the production browser renderer by `kte sheet` and inspected. This is the evidence that counts.
     118.5. A draft render with audio is the gate for motion and sync. Stills cannot judge motion.
119. Sync and the ear check. The importer repairs only what is structurally certain: a closing `!)` glued to a word whose end runs past the next onset is clamped to the next onset; a chant glued to the following line's first word is split at the line boundary. Raw times are always kept beside repaired ones. Everything else uncertain (estimated count-in times, a smeared word such as "Philly") goes on the ear check list with its time, and is not changed automatically. An item is resolved by a listener, or by agreement within 150 ms (ours) between the alignment and a local Whisper word timing run on Thing 2. Who listens is not decided by this design.
120. Variety. The report lists each entrance's share of the film, runs of the same entrance on consecutive lines, and runs of the same rest angle. It flags a share over 25 percent and any run of three (ours). It blocks nothing. `repeat: 'intended'` removes a line from the run count. Quotas are used in exactly one place: `kte draft` diversifies its own automatic suggestions.
121. Golden frames. `check/golden` renders fixture boards to an SVG string in node with `react-dom/server` and stores a hash per fixture frame. It is a regression alarm for engine changes only. It is not evidence of how a frame looks, and no still from node is shown to anyone as a preview until a parity test against the browser passes (item 164).
122. The effects reel. `fixtures/reel` is one score that plays every catalogue effect once, labelled. It is the visual acceptance test for a new or promoted effect and the menu a storyboard is written from.

## Section 7. Versioning and release

123. Freeze first. The working tree has 31 modified and 47 untracked files over HEAD `3b1228f`. Several effects in Section 3 exist only there. The first act is to commit it.
     123.1. Run `tsc --noEmit` (exits 0 today) and the board validator on the example.
     123.2. The stray detached worktree `Kinetic Type Engine HEAD check/` inside the repo is not committed. The main agent adds it to `.gitignore` for the commit and reports it; removing it is a deletion and follows his deletion rules.
     123.3. Commit everything else as one commit named "Working tree as of 21 November 2026", then tag `v0.9.0`.
124. `v0.9.0` is the legacy interface that the existing films were made with. `v1.0.0` is reserved for the first release that has the score, the compiler, the host and `kte`. This overrules Neon's proposal to tag the current tree `v1.0.0`; the reason is that 1.0.0 should mean the interface new films are written against.
125. Existing films (Ball Don't Lie, En Fuego, DOGEfather, Buy This IPO, Right Chip Wrong Huang) alias the engine working tree by relative path. They are finished and are not migrated. Once engine defaults change (shadows off, safe-box rig), re-rendering one of them from the working tree would change its picture. If one ever needs a re-render, its alias is pointed at an installed `v0.9.0` release first. This is recorded in the engine README, not by editing those films now.
126. Version meaning: patch means no golden hash changes; minor means new effects or fields and no existing golden hash changes; major means an existing score can render differently.
127. What a release locks (Astra's list, adopted): engine source, fonts and font metrics, renderer dependencies through the lockfile, the score schema version. The film locks its song map, audio file and edit list in `film.json`.
128. How improvements flow back:
     128.1. A film may define local effects in `<film>/effects/` under the `film:` namespace with `defineEffect`. `kte check` lists them.
     128.2. An effect is promoted when a second film wants it or when it is plainly general: it moves to the engine's `effects/`, gains a typed schema, declared ink and a reel entry, and ships in the next minor release.
     128.3. A fix found while making a film is made in the engine working tree, released as a patch or minor tag, and the film moves to it with `kte pin`, which shows every golden frame that changed. Films never patch engine files in place.
     128.4. Film-only seam repairs are counted. The target is zero.

## Section 9. Out of scope, and rulings on disagreements

### Deliberately out of scope for v1.0.0

143. A perspective or orbit camera. Deferred behind the proof in item 163.
144. A second renderer. Node output is used for hashes only.
145. Migrating or re-rendering the five finished films.
146. Moving or rewriting `props/`. It is only left out of the default path.
147. Splitting the engine into several packages or publishing it to a registry.
148. A graphical editor or timeline tool.
149. Automatic retiming of vocals beyond the two structural repairs in item 119.
150. Beat or chord analysis of the audio beyond the tempo already in the song map.
151. `writeOn`, `glyphMask`, `louver` and type on a path, until each has a browser fixture.

### Disagreements and rulings

152. **Variety: error or report.** Fable round 1 wanted a budget that errors; Astra wanted a playback report with quotas only for automatic picks; Neon wanted tiers with consecutive identical entrances waivable. Ruling: report only, with `repeat: 'intended'` to silence a line, and quotas only inside `kte draft` (item 120). Reason: a deliberate repeat is a legitimate device in a refrain, and a count cannot tell a device from laziness; playback can.
153. **Automatic first draft.** Astra: yes, saved in the score. Neon: opt-in flag, stamped `auto(...)`. Fable round 2: draft only, master refuses unfilled. Ruling: `kte draft` is a separate command that writes `auto(...)` into the score; a master accepts `auto(...)` fields, since by then someone has watched them, but refuses unfilled ones. Reason: the saving is real, and stamping keeps every automatic choice visible. I withdraw my refusal of `auto` in masters.
154. **Leaving the configuration singleton.** Fable: an activate bridge around the old globals. Astra and Neon: pure immutable compile from day one, with a legacy adapter. Ruling: theirs (items 16 to 19). New code is pure and takes `ctx`; `withEngine` is confined to the three legacy entry points and is deleted after v1.0.0. Reason: the wide, portrait, wide interleave test is only passable this way.
155. **Node stills versus browser evidence.** Fable round 1 proposed node stills as previews. Ruling: Astra's resolution (item 118). Node gives hashes and hulls; the browser gives every picture a person or reviewer looks at. Reason: a preview that differs from the render causes exactly the revision rounds this work is meant to remove.
156. **Packages and host.** Neon round 1: seven packages. Neon round 2, Astra, Fable: one repository, one engine-hosted runner. Ruling: one repository, eight folders, one host. Settled.
157. **Where pinned releases live.** Neon: `~/.kte/releases/<tag>/`. Ruling: `~/Experiments/Kinetic Type Engine Releases/<tag>/` (item 112). Reason: his visibility rule prefers work in plain sight over a hidden home folder, and the folder is recreatable from a tag.
158. **Tag for the current tree.** Neon: `v1.0.0`. Ruling: `v0.9.0` (item 124).
159. **Numeric thresholds.** All three proposed numbers. Ruling: Neon's three tiers with the numbers in item 117, every one a function of the safe box or the beat, every one labelled as the council's. Reason: fixed pixels are what made the giant-word rule unsatisfiable in portrait.
160. **Speed cap.** One proposal was to raise or drop `SPEED_CAP_FRACTION`. Ruling: keep the existing energy transit model as the default rule family and stop treating the flat cap as the main limit. Reason: the energy model already encodes fast travel with a readable rest, which is the Pulp Fiction behaviour.
161. **Portrait restaging.** Positions ranged from automatic restaging to hand overrides. Ruling: one score, automatic rows and camera for portrait, `portrait:` overrides where the automatic result fails, compile fails loudly with a named conflict instead of shrinking type, and the override share is reported. Reason: nobody has evidence yet for how good automatic restaging is; measuring it on Room for One will supply some.
162. **Clamping vocal durations.** Fable round 1 would clamp broadly. Ruling: Astra's (item 119): flag first, repair only the structurally certain, keep raw timing.
163. **Perspective camera.** All three now agree to defer. Ruling: deferred until a proof compares two routes on the pure-type fixture in the browser: a CSS 3D root transform, and extending the existing `turn` homography to the whole board. The proof must show the validator's hulls still match the picture. Reason: it touches the one function every check relies on.
164. **When node stills may be shown.** Ruling: only after a parity test in which at least 50 fixture frames rasterised from node output match browser frames within a stated pixel tolerance. Until then, never.
165. **Review cadence.** One proposal capped review passes. Ruling: no cap. Reason: Astra's point stands, that a cap ships known faults; the checks and the draft gate are what reduce rounds.
166. **Film-local effects.** Positions ranged from banned to free. Ruling: allowed under the `film:` namespace, listed by `kte check`, promoted with a fixture (item 128). Reason: every past film invented effects mid-production, and a ban would only push them into `raw`.
167. **Where the old line's fate is written.** Astra wrote `leave` on the outgoing line; Fable wrote `old` on the incoming one. Ruling: `old` on the incoming line, with a scene-level `exit` for the last line of a scene. Reason: the fate depends on what arrives, and the pair is the unit.
168. **Exits in the first release.** Astra moved exits and renderer smear ordering into the first release. Ruling: exits are in (items 80, 81, 86 to 88). The smear ordering claim is Neon's and unverified by me, so it is a step 3 investigation item, not a committed change.
169. **Measuring success.** Ruling: Astra's targets, adopted as the test of this design on Room for One and the film after it: at least 80 percent of lines without `raw`, zero film-only seam repairs, at most two owner correction rounds per master, a lively portrait from the same score. These are the council's targets and have not been put to him.

170. My score for this target if it is built as written: 9 out of 10. The missing point is that nothing here has been proven in a browser, and that the automatic portrait result is unknown.
