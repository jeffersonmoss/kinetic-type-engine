## Amendment 1. One reading interval per sung token

Replaces v2 items 35, 37, 38.1 and 99, the definition of `stay()` in v2 item 26, and the timing clauses of v2 items 110.1 and 110.2.

1. Every sung token has exactly one protected reading interval `[S, E]`, computed once by the compiler and used unchanged by the compile check, the board validator, the sync table and the inspection list. No check uses any other definition.
2. `S` is the token's accepted first readable frame: the first frame at which it is readable. `S` must fall from 6 frames before onset to 2 frames after onset (ours). A token marked `preset` may become readable earlier; its `S` is then fixed at onset minus 6, and it must be readable from that frame.
3. `E` is the later of the token's vocal end and `S` plus 14, so the interval is at least 15 frames.
4. Readable means all of: opacity 0.5 or more, wholly inside the safe box, not covered by other ink, at or above the size floor, contrast 4.5 or more. The token must be readable on every frame of `[S, E]` without a gap.
5. Landing (motion settled) is a separate deadline: no later than onset plus 8 frames. A token may be readable while still settling.
6. Hard errors, replacing the timing clauses of v2 items 110.1 and 110.2: `S` outside its window; any unreadable frame inside `[S, E]`; landing after its deadline. A token that first clears the threshold at onset plus 1 passes every check, because every check reads the same `S`.
7. Fates. No fate may reduce the readability of a token before that token's `E`. This applies to `stay()` as much as to the others: `stay()` leaves the old line in place at full opacity and begins the retirement dim (to 0.45) on the frame after the old line's last `E`. `dock`, `retract` and `clear` start at the later of the incoming entrance start and the frame after the old line's last `E`, unless the fate keeps every old token readable while it runs. A run kept alive as a landmark (v2 item 39) stays lit until the referencing effect's release.
8. Step 7 fixtures, replacing the two named in v2 item 130: a reply that enters while the call is held lit passes; the same passage with the call dimmed one frame before its last `E` fails; a token readable from onset plus 1 passes; a token readable from onset plus 3 fails.

## Amendment 2. A legal draft opener for every scene

Replaces v2 item 43 and adds one clause to v2 item 23.

9. A scene's `exit` is required on every scene except the last. Its draft fallback is `fade()`.
10. Draft mode. When a required field is missing, a draft compile substitutes plain fallbacks and lists each in the check report. Nothing is written to the score. A master compile refuses any fallback.
    10.1. Scene opener, in any scene: `from: opening()`, `enter: cascade(type(), {by: 'word', clock: 'sung'})`. No `old`. It never refers to the previous scene.
    10.2. Any other line: `from` is the last row of the previous line, `enter` is `rise()`, `old` is `clear(fade())`.
    10.3. Reply: `from` is the last row of its own line, `enter` is `rise()`.
11. Added to step 7's done-test (v2 item 130): after `kte new` with no edits, `kte render --draft --section v1` (a section that follows another scene) produces a clip with audio.
12. `kte draft`, which writes `auto(...)` suggestions into the score, stays in step 9.

## Amendment 3. React scoping at the actual draw calls

Replaces v2 item 20 and two rows of the table in v2 item 17.

13. `engine/scope.tsx` is a new file in the frame core that imports only `react`. It exports:
    13.1. `ScopeRunnerContext`, a React context whose value is a function `run(fn)`; the default value calls `fn` directly.
    13.2. `scoped(Component)`, which returns a function component that reads the runner with `useContext` and returns `run(() => Component(props))`.
14. Every engine component that reads configuration during render is defined through `scoped` at its definition site: `TypeStage`, `BoardView`, `WordView`, the smear stage, and any other found by grep in step 4. Because the wrapping is at the definition, the internal chain from `TypeStage` to `BoardView` to `WordView` and the smear path are covered, not only the component the host imports.
15. `context/EngineScope.tsx` renders `ScopeRunnerContext.Provider` with the value `(fn) => withEngine(ctx, fn)`. A function component body is synchronous, so the globals are correct exactly while each body runs. Legacy films render with no provider, get the default runner, and behave as today.
16. Import table rows, replacing those in v2 item 17:

| Module | May import |
|--------|-----------|
| `engine` | itself (including `engine/scope.tsx`), `react`, and `useCurrentFrame` from `remotion` in `time.ts` only |
| `context` | `engine` (types, `scope.tsx`, and `configureEngine` only in `legacyBridge.ts`), `react` in `EngineScope.tsx` |

17. The tests in v2 items 127(a) and 131.3 stand: wide and portrait with distinct fonts and palettes, rendered together and compared with each alone, in node if server rendering works and in the host in any case.

## Amendment 4. The pilot's picture check exists when the pilot runs

Replaces the command lists in v2 items 130 and 132, and adds to v2 items 131 and 133.

18. Step 7 additions. `kte check` writes a baseline `reviews/Frames to inspect.json` per format straight from `compileScore`: for each token group, its `S` frame and landing frame; the middle frame of each transition; and for each scene cut or cross-scene handoff, the frame before, the cut frame and the frame after. No hull pass is involved. Step 7 also builds a minimal `kte sheet`: it renders exactly those frames as stills through the host, in the production browser renderer, into `renders/inspection/`, and creates `reviews/Inspection.json` with one entry per frame, `{format, frame, reason, verdict: open | pass | fail, note}`. Step 7's command list becomes `new`, `ingest`, `check`, `render --draft`, `sheet`, `where`.
19. Step 8 addition, as item 131.6: one edge move run twice in each format. In the first, a line enters from `edge('B')` and its ink crosses the frame edge during the entrance, before any token's `S`; all hard checks pass and the crossing frames appear in the inspection list. In the second, the same line rests with a sung word cut by the safe box during `[S, E]`; the hard check in Amendment 1 item 6 fails and names the token and frame. Both are confirmed against the browser stills.
20. v2 item 131.5 now reads: the main agent has run `kte sheet` for both formats and recorded a verdict for every frame in `Inspection.json`; no frame of the passage is `open` or `fail`.
21. Step 9 no longer includes `kte sheet`. Step 10 is unchanged in purpose: the hull pass adds its flagged frames to the same `Frames to inspect.json`, and `kte sheet` picks them up without change.
22. `kte sheet` launches Chrome and is run by the main agent, never a sandboxed delegate.
