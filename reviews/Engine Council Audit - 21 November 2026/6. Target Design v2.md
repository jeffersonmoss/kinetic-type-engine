Written by Fable (claude-fable-5-2) as architect of the engine council, 21 November 2026. It replaces `4. Target Design v1.md` and stands on its own. It takes in the round 3 reviews by Astra (8 of 10) and Neon (7.5 of 10). Section 9 lists what changed and where I ruled against a reviewer.

### Boundaries

6. `song`. Input: audio file, Suno alignment JSON, `song.json` display spellings, `analysis/ear-check.json`. Output: `analysis/song-map.json` (schema 2) and a regenerated `analysis/Ear check list.md`. Written in TypeScript. Replaces the skill's `build_song_map.py`.
7. `score`. Pure data builders and types. No layout, no configuration.
8. `effects`. Typed effect definitions in three shapes (item 14). Pure functions.
9. `compile`. `compileScore(ctx, score, songMap)` is pure. It returns a `CompiledFilm`: frozen `Board[]` for one format, a line index (line id to board, block, first readable frame, landing frame), the transition list, reading intervals per token, and diagnostics. Each board carries its own read-only `EffectTable`.
10. `frameAt`, which is today's `engine/`. `wordStateAt(board, i, f)` stays the single state function for renderer and checks, with its signature unchanged.
11. `check`. Everything that judges a film without a browser, and the list of frames a browser must render.
12. `host`. The only Remotion project. Loads the film folder named by an environment variable, compiles once per format, registers compositions.
13. `cli`. The `kte` commands.

### How the frame core runs effects it does not import

14. Effect definitions come in three shapes, because one shape does not fit all kinds:
    14.1. `UnitEffectDef` for `enter`, `exit` and `accent`: `pose(u, unit, p, env)` and `ink(u, unit, p, env)`.
    14.2. `PairTransformDef` for `transform`: receives the outgoing and incoming blocks and returns the incoming poses, the poses of kept glyphs, and a kept-glyph mask. Glyphs in the mask are excluded from the old line's fate and change owner to the incoming block at the effect's release frame.
    14.3. `CameraRecipeDef` for `camera`: returns `RigKey[]`. It has no pose and no ink.
15. `engine/types.ts` owns the runtime interface (`VerbDef`, as today). `effects/` lowers each used definition into that interface. The compiler collects every effect a board uses, including `cascade` and `reverse` wrappers and `film:` local effects, into a frozen `EffectTable` stored on the board. `wordStateAt` resolves a verb name from `board.effects` first and from the legacy global registry second. The frame core therefore imports nothing from `effects/`, and new films depend on no global registration.
16. `cascade` targets. By row or word it lowers to separate cues with their own start frames. By syllable or glyph it lowers into the per-letter mods already returned in word state. Step 6 confirms that channel carries offset, rotation, scale and opacity per letter, and extends the type in `engine/types.ts` if it does not.

### The engine context and the legacy bridge

18. `EngineContext` is a frozen object: `{format, safeBox, fps, beatFrames, look, fonts, fontMetrics, limits}`. `limits` holds every numeric limit as a function of the safe box. New code takes `ctx` as an argument.
19. `context/legacyBridge.ts` exports `withEngine(ctx, fn)`: set the singleton from `ctx`, run `fn` synchronously, restore in a `finally`, throw if `fn` returns a promise. It is used for non-React calls only (`layoutBoard`, `wordStateAt`, `validateBoards`).
20. React rendering does not rely on `withEngine` around a JSX return, because children render after it has restored. Instead `context/EngineScope.tsx` provides `ctx` through React context, and exports `scoped(Component)`, which wraps a function component so that its own body runs inside `withEngine` with the context it reads. Every engine component that reads configuration during render (`TypeStage`, `BoardView`, `WordView`, the smear stage and any other found by grep in step 4) is exported through `scoped`. A function component body is synchronous, so the globals are correct exactly while each body runs. Legacy callers with no `EngineScope` fall back to the singleton as today.
21. Compiled boards for the two formats are separate objects, so the `WeakMap` caches keyed on `Board` cannot mix formats.

## Section 2. The score and line-card format

### Structure

22. `film({song, look, formats, scenes})`.
23. `scene(id, {ground, lines, exit})`. One scene compiles to one `Board`. Lines accumulate on the board and the camera travels between them. `exit` is how the whole arrangement leaves when the scene ends.
24. `line(id, card)`. The id is the stable song-map line id. Card fields:
    24.1. `rows`: `'auto'` (default) or an array of row specs. A row spec is a string or `{text, size}`.
    24.2. `from`: the source landmark. Required on every line that does not open the film.
    24.3. `enter`: an entrance or transform call, optionally wrapped in `cascade`. Required.
    24.4. `place`: where the line rests relative to `from`. One of `below` (default), `above`, `right`, `left`, `inside`, `overlay`, `turnCW`, `turnCCW`.
    24.5. `old`: the fate of the previous line. One of `stay()`, `dock('margin' | 'spine')`, `retract()`, `clear(exitEffect)`. Required on a line that is not a scene opener and whose `enter` does not declare `dismissesOld`. Not allowed on a scene opener; the previous scene's `exit` governs there.
    24.6. `reply`: optional second voice for ad-lib tokens, with its own `rows`, `from`, `enter`, `place`, `size`.
    24.7. `camera`: optional; default `follow()`.
    24.8. `accents`, `portrait`, `repeat: 'intended'`, `omit`: optional.
25. Required fields, after defaults and motif expansion, are exactly: `from` (except the film opener), `enter` on every line and every reply, `from` on every reply, and `old` under the condition in 24.5. Nothing else is ever an unfilled-field error.
26. Fates are score-level values, not effects. `stay()` dims the old line to the retirement level. `dock` moves and shrinks the old block to a margin or spine in board space. `retract()` plays the old line's own entrance backwards. `clear(e)` applies an exit effect. They lower to exit effects in Section 3.

### Landmarks and binding text to sung tokens

27. A landmark is `word(lineId, 'TEXT', {nth})`, `glyph(lineId, 'TEXT', 'L', {nth, part})`, `row(lineId, n)`, `rule(ruleId)`, `edge(side)`, `opening()`, or `free({x, y}, reason)`. `lineId + '.reply'` addresses a reply. If `TEXT` matches more than one token in the line and `nth` is absent, compile fails and lists the candidates.
28. Rows are bound to tokens. Reading the rows in order, the compiler aligns their text to the line's display tokens. Each displayed run keeps its token id, so a token split over two rows at a hyphen (FORTY and ONE of FORTY-ONE in portrait) stays one sung unit with one reading interval. A sung token missing from the rows is an error unless listed in `omit`. Text matching no token must be written `echo('TEXT')` and is treated as a visual echo with no sync claim. An effect that shows one run several times for repeated tokens (`repeatStack`) declares `bindsRepeats` and takes those tokens.
29. All token times pass through the film's edit list (`film.json`), which maps output time to song time. Section previews, Shorts and masters use the same mapping for audio and picture.

### Placement, size and portrait reflow

30. Size tiers are maximum cap heights as fractions of the safe box short edge (ours): `hero` 0.24, `body` 0.11 (default), `second` 0.075, which is also the sung floor. A row is set at its tier and scaled down to fit the safe box width, never below the floor.
31. Resting position. The compiler places the incoming block from the box of its `from` landmark: `below` and `above` align left edges and stack with one row gap; `right` and `left` share the baseline; `inside` fits the block in the named counter; `overlay` makes a kept run coincide with its source run (implied by `matchCut` and `slotRoll`); `turnCW` and `turnCCW` rest the block rotated 90 degrees on the board, starting from the landmark.
32. Board space and camera space are separate. `follow()` keeps the newest line upright and inside the safe box. After a turned placement the camera therefore rolls a quarter turn, and the previous line reads as a sideways margin note with `old: stay()` and no motion of its own. `dock` is the other route to a margin note: the old block moves and the camera does not roll. Using `dock` together with a turned placement is a compile error, which removes the double rotation in the v1 example.
33. `rows: 'auto'` wraps at word boundaries to the widest rows that fit the safe box width at the tier size, preferring breaks at ad-lib boundaries and punctuation. Portrait compiles the same card: rows are re-wrapped, placement is recomputed from `from`, and a `portrait` partial card overrides any field. If a block cannot fit at or above the floor, compile fails with the line id, the row and the shortfall. Type is never silently shrunk below the floor.
34. With `matchCut`, the row holding the kept run takes the source run's cap height at the transfer frame and may scale to its own tier during the effect.

### Timing of a transition pair

35. Each sung token has a reading interval: from its onset to the later of its end and onset plus 15 frames. Its first readable frame must fall between 6 frames before and 2 frames after onset (ours), unless the card marks it `preset`. Landing (motion settled) may come up to 8 frames after onset. First readable and landing are recorded separately.
36. An entrance may start at any time, including while the previous line is still being sung. Its start is the first readable target minus the time the effect needs to become readable. With `clock: 'sung'` in a cascade, each unit is scheduled to its own token.
37. `stay()` is never delayed. `dock`, `retract` and `clear` start at the later of the incoming entrance start and the end of the old line's last reading interval, unless the fate keeps every old word readable while it runs.
38. Compile fails only in these cases, each reported with line id, token and frame:
    38.1. a token loses readability (opacity under 0.5, outside the safe box, or covered by incoming ink) inside its reading interval;
    38.2. a source landmark stops being visible before the effect's release frame;
    38.3. a token cannot be made readable by its deadline.
39. Reply lifecycle. A reply belongs to its line and shares the line's fate. One exception: if a later line or reply takes a landmark inside it, the referenced run stays alive and lit until that effect's release frame.
40. Cross-scene handoff. A scene opener may take `from` a landmark in the previous scene's final arrangement only with a screen-pinned transform. The kept run is carried into the new board at its rendered screen box at the cut frame, through the engine's existing board handoff; the rest of the old scene leaves by its `exit`.

### Motifs, raw and draft mode

41. `motif(name, {lines}, {occurrences})` expands to ordinary lines. Inside the motif, ids are written `<name>.<k>`; expansion rewrites every id and landmark with that prefix to `<name><n>.<k>` for occurrence `n`. Ids without the prefix are external and left alone. Outside the motif, lines refer to the expanded id. Each occurrence may override any card field of any line.
42. `raw(id, (ctx) => Board[])` is the escape hatch. `kte check` reports its share.
43. Draft mode. When a required field is missing, a draft compile substitutes deliberately plain fallbacks and lists each one in the check report: `from` is the last row of the previous line, `enter` is `rise()` (the film opener uses `type` by word on the sung clock), `old` is `clear(fade())`. Nothing is written to the score. A master compile refuses any fallback. `kte draft`, built later, writes real suggestions into the score as `auto(...)`.

### Worked example: Room for One (LeBron Glaze)

The hook is four call and response lines and returns three times. The lead vocal is the call; the Suno ad-lib is the reply.

```ts
// score/hook.ts
import {motif, line, word, glyph, row, edge, opening, retract} from 'kte/score';
import {cascade, stamp, nest, matchCut, rise, slotRoll, repeatStack,
        turnIn, beatPunch, zoomLadder} from 'kte/effects';

export const hook = motif('h', {
  lines: {
    // "Four rings on his hand! (Room for one!)"
    1: line('h.1', {
      rows: [{text: 'FOUR', size: 'hero'}, 'RINGS ON HIS HAND'],
      from: opening(),
      enter: cascade(stamp(), {by: 'word', clock: 'sung'}),
      reply: {
        rows: ['ROOM FOR ONE'], size: 'second',
        from: glyph('h.1', 'FOUR', 'O', {part: 'counter'}),
        place: 'inside',
        enter: nest(),                              // room for one, inside the O
      },
      accents: [beatPunch('HAND')],
    }),

    // "Year twenty-four! (Still not done!)"
    2: line('h.2', {
      rows: ['YEAR', {text: 'TWENTY-FOUR', size: 'hero'}],
      from: word('h.1', 'FOUR'),
      enter: matchCut({keep: 'FOUR', pin: 'screen'}),   // FOUR never leaves the screen
      old: retract(),                                   // the rest goes back the way it came
      reply: {
        rows: ['STILL NOT DONE'], size: 'second',
        from: row('h.2', 2),
        enter: cascade(rise(), {by: 'word', clock: 'sung'}),
      },
    }),

    // "Who's still chasing? (The King! The King!)"
    3: line('h.3', {
      rows: ["WHO'S STILL", {text: 'CHASING?', size: 'hero'}],
      from: word('h.2.reply', 'STILL'),
      place: 'turnCW',                    // rests turned; follow() rolls the camera to read it
      enter: matchCut({keep: 'STILL', pin: 'board'}),
      old: stay(),                        // line 2 becomes a sideways margin note by the roll alone
      reply: {
        rows: ['THE KING!'],
        from: glyph('h.3', 'CHASING?', 'G', {part: 'foot'}),
        enter: repeatStack({clock: 'sung'}),            // binds both sung "The King!"
      },
    }),

    // "What's he chasing? (One more ring!)"
    4: line('h.4', {
      rows: ["WHAT'S HE", {text: 'CHASING?', size: 'hero'}],
      from: row('h.3', 1),
      enter: slotRoll({keep: 'CHASING?'}),              // dismissesOld: only changed words roll
      reply: {
        rows: ['ONE MORE', {text: 'RING!', size: 'hero'}],
        from: word('h.3.reply', 'KING!', {nth: 2}),
        enter: matchCut({keep: 'ING!', pin: 'screen'}), // the second KING becomes RING
      },
    }),
  },
}, {
  occurrences: {
    2: {1: {from: edge('B'), enter: turnIn({axis: 'x'})}},
    3: {1: {from: word('count.2', 'THREE'), enter: stamp()},
        3: {camera: zoomLadder({steps: 2})}},
  },
});
// (stay is imported from 'kte/score' with the other fates)

## Section 4. Taste defaults baked in

95. No drop shadows. `look.shadow` defaults to `false`; the default at `TypeStage.tsx:66` and the plate shadows at lines 113, 141 and 165 leave the default path. A look that turns shadows on is a hard check error unless `film.json` has `"allowShadow": true`.
96. No props and no figures. No score builder accepts one. `props/` is reachable only by an explicit legacy import.
97. Parentheses are removed in data: the importer strips them from display text, marks the tokens `role: 'adlib'`, keeps the raw text. Any parenthesis in rendered text fails the check.
98. Display spellings are applied in data from `song.json`. Any sung-spelling key in rendered text fails the check.
99. Legibility: a token is visible at opacity 0.5 or more for its whole reading interval, which is at least 15 frames. `VISIBLE_THRESHOLD` rises from 0.25 to 0.5. A retired word at 0.45 is outside its reading interval and not counted.
100. At most one state change per beat per block, as `BEAT_FRAMES` enforces today.
101. Size floor, giant-word limits, margins and fill box are fractions of the safe box (item 30), replacing fixed pixels that cannot be met at 720 wide. Contrast on the ground is at least 4.5 to 1 (ours). The rig centres on the safe box.

## Section 5. `kte new`: one-command setup

102. ```
kte new "Room for One" --audio "<mp3>" --alignment "<alignment json>" --suno-clip <id> --pointer "<project folder>"
```
     `--here <folder>` adopts an existing folder and overwrites nothing.

## Section 6. Checks

109. Order: score check (types, schema, ids, ambiguous landmarks, token binding); compile check (item 38, fallbacks used, `raw` share); board validator (existing rules reading `ctx.limits`, unknown handoff ids as errors, sheet and energy transit rules on by default); sync table; hull pass; variety report; golden frames.
110. Hard errors, which block a master. Picture errors here apply only to tokens during their reading interval and are computed from layout geometry and word state, not from hulls.
     110.1. A reading token cropped by the safe box, overlapped by other ink, under the size floor, under contrast 4.5, or under opacity 0.5.
     110.2. A source gone before release; a token not readable by its deadline; first readable frame more than 6 frames early without `preset` or more than 2 late.
     110.3. A parenthesis or sung spelling on screen; a shadow without the flag; a prop or figure; a missing glyph.
     110.4. Two state changes in one beat on a block.
     110.5. A draft fallback, or an open entry in `ear-check.json` for a line in the render.
     110.6. A frame marked `fail` in `reviews/Inspection.json`.
111. Waivable warnings, each waived in the score with a reason: `free` placement, a non-default lead, a rest read under 8 frames.
112. Reports, never blocking: variety, `raw` share, film-local effects, portrait override share, hull flags.
113. Viewer-true checks.
     113.1. Each effect declares ink. `legacy(name)` supplies a default box until a typed definition replaces it.
     113.2. The hull pass in node unions declared ink on every frame and flags frames where ink leaves the frame during a reading interval's neighbourhood, where blocks may collide in transit, or where per-letter motion is large. It is conservative. It selects frames; it never blocks a master and never passes one. Entrances from an edge and exits off the frame are expected and are not errors.
     113.3. Flagged frames, plus each line's first readable frame, landing frame and the middle of each transition, go to `reviews/Frames to inspect.json`.
     113.4. `kte sheet` renders them in the production browser renderer. The reviewer records a verdict per frame in `reviews/Inspection.json`. This and the draft render with audio are the evidence that counts.
114. Sync and ear check. The importer repairs two structurally certain faults only: a closing `!)` glued to a word whose end runs past the next onset in the same voice, and a chant glued to the next line's first word. Raw times are always kept. Other overlaps are preserved with their voice (lead or ad-lib) and a review status, since overlapping voices can be correct. Each uncertain spot is an entry in `ear-check.json`: `{id, tokenId, issue, status: open | verified | corrected, start, end, by, date, evidence}`. `ingest` never overwrites a verified or corrected entry and applies corrected times. An entry is closed by a listener, or by agreement within 150 ms (ours) with a local Whisper word timing. Who listens is not decided here.
115. Variety is a report: each entrance's share, runs of the same entrance, runs of the same rest angle; it flags a share over 25 percent or a run of three (ours). `repeat: 'intended'` exempts a line. Quotas exist only inside `kte draft`.
116. Golden frames. `check/golden` hashes fixture frames in node. It is a regression alarm for engine changes on the sampled frames only; unchanged hashes say nothing about other frames. No node still is shown as a preview until a parity test passes (item 153).
117. The effects reel, `fixtures/reel`, plays every typed catalogue effect once, labelled. It is a release deliverable that grows in batches.

## Section 7. Versioning and release

118. Freeze first: run `tsc --noEmit` and the example validator; add the stray worktree `Kinetic Type Engine HEAD check/` to `.gitignore` and report it (removing it is a deletion under his rules); commit the rest as "Working tree as of 21 November 2026"; tag `v0.9.0`.
119. `v0.9.0` is the legacy interface. `v1.0.0` is the first release with score, compiler, host and `kte`.
120. The five finished films alias the working tree by relative path and are not migrated. If one ever needs a re-render, its alias is pointed at an installed `v0.9.0` first. This is noted in the engine README.
121. One compatibility rule. Patch: no fixture hash changes and every existing score compiles. Minor: every existing score compiles, and any fixture frame whose picture changed, whether by new feature or bug fix, is listed in the release notes. Major: an existing score needs editing to compile. A picture-changing fix is therefore a minor release. Films are pinned, so a picture change reaches a film only through `kte pin`, which lists changed frames.
122. A release locks engine source, fonts and metrics, renderer dependencies through the lockfile, and the score schema version. The film locks its song map, ear-check file, audio and edit list.
123. Improvements flow back three ways. A film may define `film:` effects in its own `effects/` folder, listed by `kte check`. An effect is promoted when a second film wants it or it is plainly general: typed definition, declared ink, reel entry, next minor release. A fix found during a film is made in the engine and released; films never patch engine files. Film-only seam repairs are counted, with a target of zero.

### Where I ruled against a reviewer

146. **Draft bootstrap.** Astra asked to move a minimal `kte draft` forward so the sequence is `new`, `draft`, `render`. I chose Neon's compile-time fallbacks instead, so it is two commands. Reason: the fallbacks are deliberately plain and are listed in the report, so nobody mistakes them for choices, and the rule that automatic choices are written into the score still holds for `kte draft` when it arrives. Masters refuse fallbacks either way.
147. **Legacy timing baseline.** Astra asked to compare against an equivalent legacy pure-type passage. I reduced the baseline to one line pair and one correction built the legacy way (item 131.4). Reason: building the whole passage twice spends the pilot on the workflow being replaced, which is Astra's own objection to v1's fallback. The comparison is weaker as a result and should be read as indicative.
148. **Default placement and draft `old`.** Neon suggested `old: stay()` as the draft fallback. I used `clear(fade())`. Reason: with `stay()` on every line, an unfilled scene piles up lines until a block cannot fit and the draft fails, which defeats the purpose of a fallback.
149. **SSR fallback wording.** Neon's fallback is adopted, with one limit: hashes of serialised state do not exercise `TypeStage`, so if that fallback is used, the React scope test moves to the host (item 127) and the gap is recorded.
150. Earlier rulings stand unchanged: variety is a report; `auto(...)` accepted in masters; pure compile from day one; browser is the only picture evidence; one repository and one host; releases in `~/Experiments/Kinetic Type Engine Releases/`; current tree tagged `v0.9.0`; energy transit model kept; flag-first vocal repair; no cap on review passes; `film:` effects allowed; fate written as `old` on the incoming line; Astra's success targets (at least 80 percent of lines without `raw`, zero film-only seam repairs, at most two owner correction rounds per master, a lively portrait from the same score) adopted as the council's targets, not yet put to him.
151. One thing neither reviewer raised that I changed: `quarterRoll` is no longer a camera recipe an author writes. A quarter turn is now a placement (`turnCW`, `turnCCW`) that `follow()` reads, so the board and camera cannot disagree.
152. Perspective camera stays deferred until a browser proof compares a CSS 3D root transform with extending the `turn` homography to the whole board, and shows the hulls still match the picture.
153. Node stills may be shown only after at least 50 fixture frames rasterised from node output match browser frames within a stated tolerance.

154. My score for this target if built as written: 9 of 10. The missing point is the same as before: nothing is proven in a browser, automatic portrait reflow quality is unknown, and step 8 may show that the placement contract in items 30 to 34 is too simple for real passages.
